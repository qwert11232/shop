# 🤖 ТЕХНОЛАБ — админ-бот в Telegram

Бот один на магазин, но показывает разное в зависимости от того, кто пишет:

1. **Покупатель** (любой Telegram ID): свои заказы, корзина, бонусы, «как мы работаем».
2. **Владелец** (ID из `ADMIN_TELEGRAM_IDS`): панель — заявки, товары, покупатели, сводка, оплата.
3. **Уведомления**: заявка клиента уходит в группу магазина с кнопками статуса.

Права проверяются только на сервере (`src/lib/bot-access.ts`). Ни одна кнопка и ни один экран
не решают, можно ли действие.

## Две роли в одном боте

| | Покупатель | Владелец |
| --- | --- | --- |
| Команды | `/start`, `/orders`, `/cart`, `/bonus`, `/help` | `/start`, `/new`, `/products`, `/orders`, `/customers`, `/stats`, `/find`, `/help` |
| Кнопки | «Мои заказы», «Моя корзина», «Бонусы», «Как мы работаем» | очереди, товары, массовые действия, оплата |
| Что видит | только свои заказы и свой баланс | все заявки, цены, клиентов |
| Callback-префикс | `my:*` | всё остальное |

Разделение сделано в одном месте — в вебхуке:

```ts
if (!isBotAdmin(from)) { await handleClientMessage(from, chatId, command, text); return; }
```

Клиентские кнопки (`my:*`) разбираются **до** админского `switch`, поэтому нажатие чужой
кнопки не приводит в админский код — только тост «Раздел доступен владельцу магазина».

**Свой заказ по номеру.** Покупатель может прислать хвост номера (`byw78w`) — бот ищет
только среди ЕГО заказов. Чужой заказ так не открыть: выборка идёт по подписанному
Telegram `tgUserId`, а не по номеру из сообщения.

**Меню команд тоже разное.** `POST /api/bot/setup` ставит дефолтный набор (покупательский)
и отдельно для каждого админа — админский, через `scope: { type: "chat" }`.

**Если админы не настроены**, бот не закрывается: покупатели продолжают видеть свои заказы,
а подсказку про `ADMIN_TELEGRAM_IDS` получает только тот, кто пришёл с админской командой
(`/new`, `/products`, `/stats`, `/customers`, `/find`).

## Что нужно задать в переменных окружения

| Переменная | Зачем | Обязательна |
| --- | --- | --- |
| `BOT_TOKEN` | токен из @BotFather: отправка сообщений, вебхук | да |
| `BOT_WEBHOOK_SECRET` | проверка заголовка `X-Telegram-Bot-Api-Secret-Token` | да |
| `BOT_SETUP_TOKEN` | одноразовая настройка вебхука по ссылке | да |
| `ADMIN_TELEGRAM_IDS` | числовые ID админов через запятую | да |
| `ADMIN_TELEGRAM_USERNAMES` | запасной вход по username, без `@` | нет |
| `GROUP_CHAT_ID` | группа для заявок (`-100…`) или `me` — в личку админам | нет |
| `OWNER_TELEGRAM_ID` | владелец веб-админки; тоже считается админом бота | да |
| `WEBAPP_URL` | адрес мини-аппа для кнопок «Открыть витрину» | да |

**ID пока не заданы намеренно.** Пока `ADMIN_TELEGRAM_IDS` пуст, любой, кто напишет боту,
получит ответ «Доступ не настроен» и свой ID — его и нужно вписать в переменную.
Это безопасное состояние по умолчанию: «пусто» = «никому нельзя».

## Настройка за три шага

> **Пока группы нет** — заявки не теряются: при пустом `GROUP_CHAT_ID` или значении `me`
> они уходят в личку всем из `ADMIN_TELEGRAM_IDS`, с теми же кнопками статусов.
> Когда группа появится, достаточно вписать её ID в `GROUP_CHAT_ID`.

1. **@BotFather** → `/newbot` → скопировать токен в `BOT_TOKEN`.
   Там же `/setmenubutton` → URL витрины (`WEBAPP_URL`).
2. **Переменные окружения** на Vercel: `BOT_TOKEN`, `BOT_WEBHOOK_SECRET`
   (любая случайная строка из букв, цифр, `_`, `-`), `BOT_SETUP_TOKEN`, `GROUP_CHAT_ID`,
   `WEBAPP_URL`. Сделать **Redeploy**.
3. **Открыть** `https://<домен>/api/bot/setup?token=<BOT_SETUP_TOKEN>` — ответ покажет
   шаги: `getMe`, `setWebhook`, `setMyCommands`, `getWebhookInfo`. Ожидается `"ok": true`.

После этого бот в группе: добавить его в группу и **сделать администратором** (право
отправлять сообщения), иначе заявки в группу не дойдут.

## Как узнать свой ID

Написать боту `/id` — он ответит числом. Либо открыть `/api/bot/setup` без токена:
в ответе есть `admins.ids` (сколько ID настроено), но сами ID не раскрываются.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/start` | панель: заявки, товары, добавить товар, покупатели, сводка |
| `/new` | добавить товар: название → цена → категория → бренд → описание → фото |
| `/products` | товары постранично; в карточке — правка, варианты, характеристики, галерея |
| `/find` | поиск товара по названию или бренду |
| `/orders` | заказы по статусам; в карточке — доставка, трек, комментарий клиенту |
| `/customers` | покупатели: контакты, бонусный баланс, начисление и списание |
| `/stats` | сводка: заказы, выручка, средний чек, бонусы |
| `/id` | ваш Telegram ID |
| `/help` | справка |

## Добавление товара

`/new` или кнопка «Добавить товар». Бот спрашивает по одному полю и показывает черновик:
название, цена, категория, бренд, описание, фото. Обязательные — название, цена и категория;
кнопка «Создать товар» появляется, когда они заполнены.

Как это работает в чате:

1. Пришлите название — «Телевизор OLED 55». Бот заполнит первое пустое поле сам,
   кнопкой выбирать поле не нужно.
2. Пришлите цену — «89 990» (пробелы, точка как разделитель тысяч и знак ₽ допустимы).
3. Выберите категорию кнопкой. Нет подходящей — «Новая категория», бот создаст её
   и сразу подставит в черновик.
4. Бренд, описание и фото — по желанию. Фото присылается сообщением и становится обложкой.
5. «Создать товар» → карточка с кнопками «Варианты» и «Характеристики».

## Карточка товара

| Кнопка | Что делает |
| --- | --- |
| Название / Цена / Бренд / Описание | бот ждёт новое значение следующим сообщением |
| Фото | обложка карточки; файл забирается из Telegram и кладётся в хранилище |
| Галерея | дополнительные кадры фото или видео по ссылке (mp4/webm/mov) |
| Категория | переносит товар в другой раздел витрины |
| Варианты | цвет, память, комплектация с надбавкой к цене |
| Характеристики | строки «Название: значение» — из них строятся фильтры витрины |
| Скрыть / Вернуть | товар исчезает с витрины, оставаясь в базе |
| Удалить | удаляет товар с вариантами и характеристиками; заказы остаются в истории |

**Варианты** вводятся пачкой, каждый с новой строки:

```
128 ГБ -8000
256 ГБ
512 ГБ +15000
Чёрный титан
```

Число со знаком — надбавка к цене (минус разрешён: младшая память дешевле). Вид варианта
(цвет, память, комплектация) бот определяет по названию. Строки, которые не разобрались,
бот показывает в ответе — молча ничего не теряется.

**Характеристики** тоже пачкой:

```
Встроенная память: 256 ГБ
Диагональ: 6,3 дюйма
Материал: титан
```

Единица измерения отделяется автоматически («256 ГБ» → значение 256, единица ГБ), группа
подбирается по смыслу (Производительность / Экран и камера / Питание / Корпус). Одинаковое
название обновляет значение, новое — добавляется. Характеристики, у которых больше одного
значения в каталоге (но не больше восьми), попадают в панель фильтров витрины автоматически.

## Статусы заявки

```
new → contacted → done
  ↘ cancelled ↗
```

Переходы заданы в `src/lib/bot-screens.ts` (`NEXT_STATUS`): из «новой» можно взять в работу
или отменить, из «на связи» — завершить или отменить. В карточке заявки в чате и в
сообщении группы показываются только допустимые кнопки.

При смене статуса в чате бот правит сообщение в группе: дописывает статус и автора,
чтобы группа не висела с «новой» заявкой.

## Заказы и доставка

В карточке заказа: состав с вариантами и количеством, сумма, списанные и начисленные бонусы,
имя и телефон клиента, кнопка «Написать» (открывает чат с покупателем).

| Кнопка | Что делает |
| --- | --- |
| Дальше: <шаг> | переводит доставку на следующий шаг: Собирается → Передан в доставку → Ждёт в ПВЗ → Получен |
| Собирается / В доставку / Ждёт в ПВЗ / Получен | любой шаг вручную |
| Трек-номер | бот ждёт номер посылки; клиент видит его в кабинете |
| Комментарий | текст для клиента: причина отмены, время доставки |
| Отменить заказ | статус «Отменён», бонусы возвращаются клиенту |

При отмене списанные бонусы возвращаются на баланс, а начисленный кешбэк снимается
(не больше остатка). Сообщение в группе правится тем же статусом.

## Покупатели и бонусы

`/customers` — последние покупатели с балансом и числом заказов. В карточке:

- «Начислить бонусы» — сумма в рублях: `500` начислит, `-200` спишет
  (списать больше баланса нельзя);
- баланс, телефон, реферальный код и Telegram ID — для связи.

## Как это устроено

- `src/lib/bot-screens.ts` и `bot-screens-admin.ts` — экраны: данные → текст и кнопки, без сети;
- `src/lib/bot-admin-flow.ts` — действия с данными (создать товар, варианты, характеристики, бонусы);
- `src/lib/bot-input.ts` — разбор ввода: цена, варианты, характеристики, телефон;
- `src/app/api/bot/webhook/route.ts` — разбор апдейта и отправка сообщений.

Состояние диалога («жду цену», черновик товара) хранится в таблице `bot_state`, а не в памяти
процесса: на Vercel инстансы сменяются, и состояние из памяти пропадало бы при холодном старте.
Запись живёт 15 минут и одноразовая; черновик товара переживает смену инстанса, потому что
лежит в базе, а не в памяти.

## Диагностика

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Бот молчит | `BOT_TOKEN` не задан или вебхук не установлен | открыть `/api/bot/setup?token=…`, смотреть `steps` |
| `/api/bot/webhook` отвечает 403 | не совпал `BOT_WEBHOOK_SECRET` | переоткрыть setup: он переставит вебхук с новым секретом |
| Бот отвечает «Доступ не настроен» | пуст `ADMIN_TELEGRAM_IDS` | вписать ID из ответа бота |
| Заявки не приходят никуда | бот не админ группы, неверный `GROUP_CHAT_ID` или пуст `ADMIN_TELEGRAM_IDS` | `/api/health` → поле `ordersTo`: `group`, `admin-dm` или `нет` |
| «Хранилище фото не настроено» | нет `S3_BUCKET` на Vercel | задать S3-переменные |

## Проверка без Telegram

```bash
npm run check:bot
```

Проверяет доступ (чужой не админ, пустой конфиг закрывает всё), тексты и кнопки экранов,
экранирование пользовательских данных, смену статусов, выручку, правку и скрытие товара,
одноразовость состояния диалога, а также всю панель: разбор цены и вариантов, создание товара
из черновика, категории, характеристики с единицами, обложку и галерею, удаление, бонусы
и отмену заказа — на настоящей базе, без сети.

## Очереди работы на главном экране

`/start` отвечает на вопрос «что делать сейчас», а не показывает всё подряд.
Сверху три очереди, каждая — кнопкой со счётчиком:

| Очередь | Что это | Что делает владелец |
|---|---|---|
| Ждут подтверждения | клиент оформил, решения ещё нет | «Подтвердить заказ» |
| Ждут оплаты | подтвердили, оплата не отмечена | сверить перевод → «Оплата получена» |
| Отправить | оплачено, посылка не ушла | собрать → «Отправлено» → трек |

Если очередь пуста, меню пишет «Срочных дел нет» вместо трёх нулей. Когда
реквизиты не заполнены, под сводкой висит предупреждение: клиент не узнает,
куда платить.

## Оплата

Кнопка «Настроить оплату» → четыре поля, каждое меняется сообщением:

| Поле | Что вводить | Куда попадает |
|---|---|---|
| Реквизиты | карта или телефон СБП | в сообщение «заказ подтверждён» |
| Ссылка | ЮKassa, Т-Банк, Robokassa | отдельной строкой в том же сообщении |
| Приписка | «Чек пришлём в чат» | под суммой |
| Телефон | для связи | в подтверждение и в отмену заказа |

Ссылку можно прислать без `https://` — схема допишется. Пришлите `-`, чтобы
стереть поле. Значения хранятся в таблице `settings`, а не в переменных
окружения: их правка не требует пересборки деплоя.

Пока не заполнено ничего, клиенту приходит не «оплатите по реквизитам» (он
упрётся в пустоту), а просьба написать менеджеру.

## Поиск заказа

«Найти заказ» принимает номер заказа (можно хвост — последние 4–5 символов),
телефон или имя клиента. `%` и `_` в запросе экранируются, поэтому «100%» не
превращается в шаблон LIKE и не находит все заказы.

## Массовые действия

Товары → «Массовые действия» → категория. Внутри:

- **Скрыть все** — товары уходят с витрины, но остаются в базе и админке;
- **Показать все** — возвращает на витрину;
- **Изменить цены** — процент от −50 до +50, кнопками `+5%` / `+10%` или своим
  числом. Считается от текущей цены и **округляется до рубля**, иначе после
  «+10%» на витрине появляются цены вида 39 590,10 ₽. Минимальная цена — 1 ₽.
  Надбавки вариантов (память, цвет) процент не трогает.
- Повторное действие честно отвечает «0 изменений», а не делает вид, что сработало.

## Почему кнопка витрины — `web_app`, а не ссылка

Витрина — Telegram Mini App. Данные покупателя приходят в `Telegram.WebApp.initData`,
и только внутри Telegram. Обычная inline-кнопка с `url` открывает сайт в браузере:
`initData` там пустой, сервер не знает, кто пришёл, — покупатель становится гостем,
и корзина с заказами не работают.

Поэтому все точки входа используют `web_app`:

```ts
{ text: "Открыть витрину", web_app: { url: appUrl() } }
```

То же и для кнопки меню слева от поля ввода: `/api/bot/setup` вызывает
`setChatMenuButton` с типом `web_app`. Если оставить `default`, у покупателя
не будет точки входа в приложение вовсе.

Кнопка «Открыть в витрине» в карточке товара ведёт на `?product=<id>` —
приложение читает параметр при старте и сразу открывает товар, а адрес
чистит через `replaceState`, чтобы обновление страницы не возвращало назад.
