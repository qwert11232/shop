# 📝 Бриф: ТЕХНОЛАБ — Telegram Mini App магазина техники (2026-11-04)

## 1. Цель

**Что делаем:** Telegram Mini App «витрина» магазина техники **ТЕХНОЛАБ**. Владелец группы
публикует товары (фото, описание, цена) и категории; покупатель выбирает товар и оформляет
заявку — заявка приходит сообщением в группу Telegram.

**Какую проблему решаем:** сейчас витрина — это посты в группе; нет удобного каталога
с фото/ценами и внятного способа «забронировать» товар.

**Для кого:** участники Telegram-группы магазина; открывают с телефона.

**Метрика успеха:** заявка на товар оформляется за ≤ 3 касания и появляется в группе в течение 5 секунд.

**Вне рамок v1:** онлайн-оплата, корзина, чат с продавцом в приложении, мультиязычность.

## 2. Стек и окружение

| Параметр | Значение |
| --- | --- |
| Язык / фреймворк | TypeScript + Next.js 15 (App Router) + React 19 |
| Стили | Tailwind CSS v4, токены в `src/app/globals.css` |
| База данных | dev: SQLite (better-sqlite3); prod: PostgreSQL (Neon/Supabase, `db-setup.sql`) |
| Хостинг | Vercel (или любой Node) + managed Postgres |
| Аутентификация | Telegram WebApp initData, HMAC-SHA256; владелец = `OWNER_TELEGRAM_ID` |
| Внешние интеграции | Bot API: `sendMessage` в группу (`GROUP_CHAT_ID`) |
| Обязательные ограничения | секреты только в env; фото ≤ 8 МБ; цена хранится в копейках (int) |

**Переменные окружения:** `DATABASE_URL`, `BOT_TOKEN`, `GROUP_CHAT_ID`, `OWNER_TELEGRAM_ID`,
`WEBAPP_URL`, `ALLOW_DEV_NO_AUTH` (см. `.env.example`).

**Существующий код:** нет, проект с нуля поверх каркаса `.ai/`.

## 3. Логика

**Основной сценарий:** открыл приложение из группы → выбрал категорию → выбрал товар →
нажал «Оформить заказ» (опционально комментарий) → увидел подтверждение; в группе появилось
сообщение «🛒 Новая заявка — ТЕХНОЛАБ: 📦 позиция, 💰 цена, 👤 клиент, 💬 комментарий».

**Данные:** `categories 1—N products 1—N orders` (SQLite локально, `db-setup.sql` для PostgreSQL).

**Краевые случаи:** повторное нажатие — фронт блокирует кнопку; товар скрыт — 404;
initData протух (>24 ч) или подделан — отклоняем; бот не настроен — заявка пишется в БД,
клиенту показываем текст (режим демо); пустая категория — осмысленное пустое состояние.

**Права:** гость видит каталог и может оставить заявку; владелец (`/admin`) — добавляет
категории/товары, грузит фото, смотрит заявки.

## 4. Критерии приёмки

- [ ] Каталог грузится из `/api/catalog`, категории фильтруют товары.
- [ ] `POST /api/orders` создаёт заявку и (при `BOT_TOKEN`+`GROUP_CHAT_ID`) отправляет сообщение в группу.
- [ ] Админка отклоняет не-владельца (403) и принимает владельца.
- [ ] Можно загрузить фото и опубликовать товар — он сразу в каталоге.
- [ ] `tsc --noEmit` и `next build` проходят; секреты вне репозитория.
- [ ] Дизайн: тёмная тема, acid-акцент, шрифты Unbounded/Manrope (см. `docs/DESIGN.md`).

## 5. Ограничения по процессу
