### Шаг 4: Редизайн в три цвета, SVG-иконки, аудит скиллами (2026-11-05)
- Контекст: владелец забраковал тёмную «лабораторию» (acid-лайм, фиолетовое свечение, Unbounded, эмодзи-иконки). Требование: три цвета — белый, чёрный, красный; SVG вместо эмодзи; ближе к языку Apple; свериться со скиллами по дизайну.
- Решение: развёрнуты скиллы `Vanszs/Anti-AI-UI` и `funboy322/avoid-ai-design` (раскомментированы в `skills.txt`, `.ai/skills/` в gitignore). Их сканер нашёл в прежнем UI P0 `C1` (фиолетовый градиент), P1 `SD2` (near-black + acid), `K3` (glassmorphism), `I2` (эмодзи), `I3` (люцидовый спаркл). Палитра сведена к `paper/ink/signal`, служебные оттенки — ступени чёрного (`ink-2` 4.54:1, `ink-3` только крупный кегль). Гарнитура одна — Manrope 400–700 (Unbounded убран: вторая гарнитура «для характера» — тоже штамп). Иконки — собственный SVG-набор в `src/components/icons.tsx` (один штрих 1.75, `currentColor`). Радиусы — ступени 10/14/18. Тени, градиенты, `backdrop-blur` удалены; `prefers-reduced-motion` добавлен глобально. Эмодзи убраны из UI, в том числе из формы категорий и seed; в тексте заявки Telegram оставлены осознанно (`avoid-ai-design-ignore-file: I2`). `docs/DESIGN.md` переписан как контракт.
- Альтернативы: тёмная тема с красным акцентом — отклонено: остаётся SD2-кластером (near-black + один яркий сигнал); `next/image` вместо `<img>` — по-прежнему невозможно из-за динамических доменов фото; библиотека иконок (lucide) — отклонено: 12 иконок дешевле нарисовать, чем тащить зависимость и получать штамп I3.
- Риски: `ink-3` не проходит AA для мелкого текста — допустим только для подписей ≥14px и плейсхолдеров; красный как единственный сигнал нельзя размножать, иначе экран станет «тревожным».
- Проверка: `npm run lint` (0), `npm run typecheck`, `npm run build`, `npm run db:seed` (6/17), `detect.mjs src` → 0 findings; в собранном CSS только `#fff/#0a0a0a/#e00b20` и ступени чёрного; эмодзи в HTML `/` и `/admin` отсутствуют (проверено регуляркой); dev + curl: каталог 200, заявка 200, дубль 429, админ-заявки с полями; классы `bg-paper/text-signal/border-rule` присутствуют в CSS-бандле.

### Шаг 3: Прод-инфраструктура — PG, S3, лимиты в БД, линтер (2026-11-05)
- Контекст: после Шага 2 в бэклоге остались четыре дефекта, мешавшие деплою: код умел только SQLite, фото писались на read-only ФС Vercel, антифлуд жил в памяти процесса, линтера не было.
- Решение: `src/lib/db.ts` — адаптер (`all/get/run`, плейсхолдеры `?`) с двумя динамически загружаемыми диалектами: `db-sqlite.ts` и `db-postgres.ts` (`?`→`$n`, пул `pg`, SSL по `sslmode`). `repo.ts` стал асинхронным, boolean-литерал и имена колонок приведены к нижнему регистру PG. Лимиты вынесены в таблицу `order_limits` (`reserveOrderSlot`). `src/lib/storage.ts` — драйвер S3 (`@aws-sdk/client-s3`, ленивый импорт) или локальный; на Vercel без S3 ответ 501 вместо потери файла. Добавлены `eslint.config.mjs` (next/core-web-vitals+typescript, `no-img-element` выключен осознанно — URL фото динамические), скрипты `lint/check/check:pg/check:storage`.
- Альтернативы: Prisma/Drizzle — отклонено (нет сети к binaries.prisma.sh; Drizzle тянет генерацию миграций, а схема одна); `next/image` вместо `<img>` — отклонено: домены фото задаются в рантайме (S3/CDN), remotePatterns статичны; Redis для лимитов — отклонено: лишняя инфраструктура, БД уже есть; Vercel Blob — отклонено: привязка к платформе, S3-совместимость покрывает R2/MinIO/AWS.
- Риски: адаптер требует, чтобы `?` в SQL был только плейсхолдером (соглашение зафиксировано в `db.ts`); PG-путь проверен на pglite, не на боевом PG; локальная сборка `better-sqlite3` требует `nodedir`.
- Проверка: `npm run check` (lint 0 ошибок, typecheck, 14 утверждений storage, 8 утверждений PG на pglite), `npm run build`, `npm run db:seed` (6/17, идемпотентно), dev + curl: заявка 200, дубль 429, лимит 5/мин, upload local 200 / txt 400, чужие хосты 403, поля API совпадают с типами фронта.
